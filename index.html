    Como trabalho

    1. Primeiro a regra, depois o código. O que o sistema aceita, recusa e mostra é escrito e numerado antes; os testes conferem a regra.
    2. Nada toca produção sem combinar. Simuladores, cópias locais e banco somente leitura até a regra estar aprovada.
    3. Quem usa não precisa de terminal. Atalhos, LEIA-ME simples e retomada automática quando algo cai.

    O código é escrito com o apoio do Claude Code, a partir dos requisitos e das regras definidos para cada sistema. Senhas e chaves ficam fora do Git, em arquivos .env, sem valor padrão no código.

    Agentes de IA

    Como configuro os agentes que uso no trabalho

    Um agente só é útil se souber as regras do negócio e tiver limites claros. É isso que configuro: contexto, procedimentos repetíveis e verificações automáticas.

    Claude Code · Anthropic

    Agente de desenvolvimento com memória do projeto

    Uso o Claude Code ligado a uma base de conhecimento em Obsidian versionada com Git, o "segundo cérebro". O agente lê o contexto do projeto antes de qualquer tarefa e segue procedimentos que eu escrevi.

    .claude/
    CLAUDE.md  # regras e contexto
.claude/
├─ skills/
│  ├─ registrar-no-brain/  # decisões
│  └─ revisar-regras/      # regras
├─ agents/
│  └─ engenheiro.md        # revisa
└─ settings.json           # hooks
brain/     # Obsidian + Git
├─ sistemas/  processos/  decisoes/
hook pre-commit → sem dados pessoais
    • Contexto antes de agir: o CLAUDE.md aponta para o segundo cérebro, então o agente conhece sistemas, tabelas e regras de negócio sem eu repetir a cada sessão.
    • Skills: procedimentos repetíveis, como registrar uma decisão ou revisar uma regra, viram comandos que o agente executa sempre do mesmo jeito.
    • Verificação automática: um hook no Git impede que dados pessoais de clientes entrem no repositório.
    • Subagentes: um agente "engenheiro" revisa a arquitetura antes de qualquer mudança em banco ou robô.
    Hermes Agent · código aberto

    Agente de rotina que acompanha meus projetos e me avisa

    O Hermes cuida dos meus fluxos de IA e acompanha os projetos entregues aos clientes. Toda hora, à tarde, ele me envia um ping dizendo se algum projeto dentro do prazo de garantia está ativo com problema. Quando identifico algo errado, passo o caso para o Claude Code.

    ~/.hermes/
    config.yaml  # modelo e canais
SOUL.md      # persona e tom
skills/
├─ projetos-clientes/  # acompanha entregas
└─ garantia/           # prazo e status
memory/      # projetos, prazos, clientes
cron/
└─ tarde, a cada hora  # ping p/ mim
gateway → mensagens para mim
    • Rotina sem eu pedir: as tarefas rodam em horário fixo; eu só recebo o resultado.
    • Memória dos projetos: ele guarda o que foi entregue a cada cliente e até quando vale a garantia.
    • Ping de hora em hora, à tarde: um resumo curto dizendo se há projeto em garantia ativo com problema.
    • Escalonamento: o Hermes detecta, eu decido e o Claude Code corrige e documenta.
